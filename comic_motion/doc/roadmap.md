# 路线图（roadmap）

> 定位：**方向性规划，非排期承诺**。优先级与排期随嵌入方反馈调整。
> 任何路线落地都不得破坏两条既有红线：核心包纯 Dart 零 Flutter 依赖；
> 同 seed + 同 config 逐字节复现契约。每项标注：价值 / 工作量级 /
> 依赖决策点。
>
> 工作量级口径：**S** ≤ 2 天 ｜ **M** ≤ 1 周 ｜ **L** 2–4 周 ｜ **XL** > 1 月
> （以单人专注开发计，含测试与文档）。

---

## R1 GPU 实时路径（2.0 级候选）

**现状**：本库是预渲染路线——动效在离线管线里烘焙成 GIF/APNG/帧集，播放
端零计算。实时性受限于「离散相位采样 + 帧集磁盘/内存体积」。

**方案**：Flutter `FragmentShader`（fragment program API）实时化
**参数化变换类效果**——`parallax` / `breathing` / `lightSweep` /
`vignette` / `heartbeat` 这类纯 UV 变换 + 像素级光照的效果，一个贴图 +
几个 uniform 即可驱动，60fps 连续相位、任意插值。**粒子类**（`ambient`
等）次之：粒子状态要么编码进大 uniform 数组（数量受限），要么需要
compute/SSBO，fragment 表达受限，列为二期。

**价值**：
- 交互视差从「离散帧集阶梯感」升级为连续相位（陀螺仪/触摸全程跟手）；
- 内存从「帧集常驻」降到「单张贴图 + 深度图集」（约为帧集路径的
  1/steps）；
- 光影类效果质量上限提高（真彩色 + 无帧间量化）。

**落点**：独立 shader 伴生包（`comic_motion_shaders` 之类），与纯 Dart
核心**完全隔离**；分层结果经核心包新增的「分层图集导出通道」复用（图层
PNG + 深度/羽化掩码打包，见决策点 ③）。

**工作量级**：**L**（shader 移植每个效果 1–3 天 + 伴生包脚手架 + 图集
导出通道 + Impeller/Skia 双后端验证）。

**依赖决策点**：
1. **分层图集导出**是核心包新 API（导出形态参数，与 V1/V2 同纪律：不进
   config 序列化），需单独评审后实施；
2. **Web/桌面兼容**：FragmentShader 在 Impeller（iOS/Android 默认）与
   Skia（Web/桌面兜底）的行为差异需要矩阵验证；
3. **基线**：Flutter ≥ 3.22（与伴生包约束一致），不为此抬高整体基线。

## R2 AI 深度 / 主体检测

**现状**：深度估算为纯启发式（`depth_splitter.dart`：亮度/边缘/位置
先验 + 平滑上采样 + 羽化掩码）。漫画分格的常规构图表现稳定；复杂分格、
跨格气泡、主体与背景对比度低的场景会失准，且各切分单元独立估深，跨片
运动可能错位（README「输入格式矩阵」已注明）。

**方案**：单目深度 / 显著性主体模型（开源轻量模型 + 量化）产出逐像素
深度图，替换或校正启发式先验，分层 API 接受外部深度图注入。

**价值**：语义级分层质量跃升——人物/主体从背景正确分离，是「观感对齐
鸿蒙」在复杂画面上的最后一块拼图。

**权衡**：ML 推理与「零原生依赖」卖点直接冲突。可行落位按侵入度排序：
1. **服务端**（首选）：`comic_motion_server` 增加深度图端点 / CLI
   `--depth-map` 输入——原生依赖只落在服务端，客户端包依旧纯 Dart；
2. **可选伴生包**：端侧推理（平台通道 + 各平台推理运行时），opt-in，
   核心不感知；
3. 端侧 FFI 直连：破坏纯度面最大，不推荐。

**工作量级**：**XL**（模型选型/量化/许可审查 + 推理适配 + 深度图注入
API + 回归评估集）。

**依赖决策点**：
1. **卖点边界**：是否接受「服务端/可选包有原生依赖、核心保持零」的
   分层卖点口径；
2. **模型来源与许可**：开源单目深度/显著性模型的推理许可与再分发条款；
3. **深度图注入 API** 属核心包新接口（输入数据，非 config 参数），需
   单独评审。

## R3 分格感知分层（R2 的中间态）

**定位**：不做语义理解，先做**几何理解**——分格线检测 → 逐格独立分层
→ 重组。是 R2 落地前提升复杂分格场景质量的最务实路径。

**方案**：纯 Dart 投影剖面 + 边缘检测定位分格线（横/纵白隙），每格独立
走现有「估深 → 分层」管线，格间运动边界即分格线（天然无跨格错位）。
`StripSplitter` 的切片与尾片处理经验可直接复用。

**价值**：跨格气泡 / 多格拼版不再被整页分层混淆；每格分层质量独立可控；
为 R2 的「逐格深度」铺数据结构。

**工作量级**：**M**（检测器 + 重组器 + 与 strip 模式的关系梳理）。

**依赖决策点**：
1. **误切兜底**：分格线漏检/误检时回退整页分层（默认安全路径）；
2. **与 strip 模式的关系**：正交叠加（先条漫切片、片内再分格）还是合并
   成统一「切分器」抽象——倾向前者，实现时确认。

## R4 animated WebP 备选（opt-in 输出格式）

**现状**：`doc/webp_research.md` 调研结论——`image` 4.10.1 已内置动画
WebP 编码（VP8/VP8L + ANMF 容器），零新增依赖即可实现。V3 决策选
**APNG** 的决定性原因：APNG 走流式容器（内存 O(单帧)，与帧序列管线
同构），WebP 编码器需**整帧序列驻留内存**（1080p × 48 帧量级达数百 MB，
移动端不可行）；APNG 体积与浏览器支持在本场景并不吃亏。

**激活条件**（满足其一再评估）：
1. `image` 包支持流式/逐帧 WebP 编码（关注上游 issue 进展）；
2. 出现体积强敏感场景（真彩色体积 ≈ GIF 的 1/3–1/2），且运行端内存
   宽裕（桌面/服务端批量管线先行）；
3. 真彩色动图在 iOS 端需要非 APNG 容器的兼容性回退。

**工作量级**：**S**（适配输出通路 + opt-in `outputFormat` + 逐字节契约
按「锁定版本内」口径回归）。

**依赖决策点**：
1. `image` 包升级会改变既有编码字节——复现承诺按 README「复现承诺与
   边界」的锁定版本口径执行，升级须走版本对齐流程
   （`doc/release_checklist.md`）；
2. WebP 有损模式的确定性边界（编码器内部无随机，但量化决策与版本绑定）。

## 非目标（明确不做）

- **视频编码输出**（WebM/MP4）：必须原生依赖，与核心纯度冲突；嵌入方
  需要视频可自行转码帧序列。
- **核心包引入 Flutter / 原生依赖**：任何路线都以伴生包形态落地。
- **实时交互渲染进核心包**：GPU 路线归 R1 的独立 shader 包。
